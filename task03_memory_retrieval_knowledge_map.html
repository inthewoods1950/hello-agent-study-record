Memory & Retrieval 知识地图

这不是章节目录，而是一张“系统如何记住、如何找回、如何把信息交给 Agent”的结构图。 建议先看「总览」，再按模块展开。可搜索关键词，例如：Qdrant、HyDE、Semantic Memory。
核心概念 正确心智模型 常见误区 / Failure Mode Agent 集成 最终项目映射
0. 总览：Chapter 8 其实只有两条主干
Write Path（怎么记）
新信息→ Encoding / Parse / Classification→ Chunk / Embedding→ Storage / Index→ Consolidation / Forgetting
Read Path（怎么想起来）
当前问题→ Route→ Memory / RAG Retrieval→ Candidate Pool→ Rerank→ Context→ LLM
总原则：系统不是“存得越多越好”或“模块越多越聪明”。每增加一个模块，也增加一个潜在 failure point。
1. History vs Memory
HistoryMemory
当前 Agent 实例中的有序消息可管理、可检索、可强化、可遗忘的信息资产
通常随实例生命周期存在部分类型可持久化
主要是 user / assistant / tool 消息可包含 importance、timestamp、metadata、embedding 等
一句话：“模型记得上一句话” ≠ “系统拥有长期记忆能力”。
2. 四类 Memory
Working Memory：我现在正在处理什么？短期、容量有限、可 TTL、运行时为主。
Episodic Memory：发生过什么？事件 + 时间 + 上下文。
Semantic Memory：我知道什么？稳定事实、规律、偏好、概念、抽象结论。
Perceptual Memory：我感知到了什么？图片、音频、视频、OCR、图表等多模态输入及其特征。
关键关系：Episodic 是 evidence；Semantic 是 abstraction；Perceptual 是 raw evidence 的来源之一。
3. Memory Lifecycle
Encoding→ Storage→ Retrieval→ Consolidation→ Forgetting
Importance：是 memory policy 的信号，不是真理分数。
Reinforcement：重复出现的信息可以提高 importance，但 repetition ≠ truth。
Consolidation：例如多次 Episode → 抽象成 Semantic。
Forgetting：降低噪声，避免 Memory 无限膨胀。
成熟系统应额外区分：importance、confidence、source、last_verified。
4. Memory Policy / 分类策略
Rule-based classifier：关键词命中容易高估效果；对 use/mention、否定、上下文很脆弱。
LLM classifier：语义理解更好，但仍会误判、格式错误或返回 None。
Hybrid：高置信规则处理明显情况，其余交给 LLM，再经过 Parser + Validator + Retry。
Input→ Rules→ LLM→ Parser→ Validator→ Memory Type
5. Persistence / SQLite / Qdrant
Persistence：程序死了，数据没死。
SQLite：保存完整结构化记录——content、user、importance、timestamp、metadata。
MiniLM / Embedding：把文本翻译成向量。
Qdrant：保存 / 索引 / 搜索向量，回答“哪个 ID 在语义空间里更近？”
同一个 memory_id 把 Qdrant 的向量结果与 SQLite 的完整记录 join 起来。
Mnemonic：MiniLM = 翻译；Qdrant = 找人；SQLite = 查档案。
6. Qdrant Local vs Server
Local Mode：Qdrant 嵌在 Python 进程里，直接读写本地文件，无 HTTP。
Server Mode：Python Client 通过 HTTP/gRPC 连接独立 Qdrant Server。
不是“本地就用 CPU、Server 就不用”。Server 也可以跑在本机 Docker，照样吃本机 CPU/RAM。
Local Mode 限制：同一 storage folder 不适合多个 Client 并发打开；payload index 也不是完整 Server 行为。
7. Embedding：从文本到 384-D 向量
Text→ Tokenizer→ Tokens/Subwords→ Transformer→ Contextual Token Embeddings→ Mean Pooling→ Sentence Embedding
all-MiniLM-L6-v2：输出 384 维句向量。
[PAD]：为了 batch 对齐；attention_mask=0，不参与 pooling。
[CLS] / [SEP]：特殊 token；在该 pooling 方案中属于有效 token。
384 维不是 384 个可解释的人类概念。它是 latent distributed representation。
8. Normalize / Dot / Cosine
Vector length：\(||A||=\sqrt{\sum a_i^2}\)
Dot Product：\(A·B = ||A||||B||\cos\theta\)，混合长度和方向。
Cosine：只比较方向；归一化后 dot ≈ cosine。
Similarity score 不是 probability。0.8 ≠ “80% 相关”。
Embedding 更像“主题/语义相关”而不是“逻辑一致”。“喜欢无糖”和“讨厌无糖”仍可能很接近。
9. Top-K / Threshold / Precision / Recall / F1
Top-K：固定最多取几个。
Threshold：最低分数门槛。
Precision：捞上来的结果有多干净。
Recall：真正相关的内容捞回来多少。
F1：Precision 和 Recall 的调和平均；压缩成单值但会丢 trade-off。
Signal Detection 对应：similarity≈evidence strength；threshold≈criterion；TP≈hit；FP≈false alarm。
Operating point：某个 threshold 对应的 (Recall, Precision) 坐标。
10. ANN / HNSW
Exact Search：Query 与所有 vector 比较。
ANN：Approximate Nearest Neighbor，不扫全量，用索引换速度。
HNSW：多层图，不是树。高层稀疏、负责远距离导航；Layer 0 最密。
高层节点不是“更重要”。通常来自概率式 promotion。
Greedy local minimum：只走“眼前更近”的路可能错过 global best。
Candidate Pool：同时保留多个搜索分支，降低单一路径卡死风险。
11. Metadata Filter
Filter 决定谁有资格参赛；Similarity 决定参赛者怎么排序。
适合 hard filter：user_id、memory_type、time range、namespace。
Importance 不一定适合 hard filter。高相关但 importance 略低的信息可能被直接排除。
12. Memory vs RAG
Memory：关于用户、Agent、自身历史的信息。
RAG Knowledge Base：外部文档、资料、知识库。
Memory ≠ RAG。Memory 只是可能成为 Retrieval source 之一。
典型区分：“我之前学过什么？” → Memory；“Cross-Encoder 原理是什么？” → RAG。
13. Document RAG
Document→ Parse / OCR→ Chunk→ Embedding→ Vector Store→ Retrieve→ Context→ LLM
Parse：把当前表示转换成下一阶段程序能明确处理的结构。
OCR：从图像像素识别文字；它不等于 chunking，也不天然消耗 LLM token。
Retrieval relevance ≠ answer sufficiency。相关资料不一定足够回答问题。
14. Chunking / Overlap / Neighbor Expansion
Chunk 太小：语义纯，similarity 可能高，但上下文不完整。
Chunk 太大：信息完整，但 semantic noise 和 token 成本增加。
Overlap：降低关键关系被 chunk boundary 切断的概率。
Overlap 太大：重复 embedding、存储、检索、Context。
HNSW adjacency ≠ Document adjacency。需要 doc_id / chunk_index 才能做邻居扩展。
成熟组合：中等 chunk + 小 overlap + neighbor/context expansion。
15. MQE / HyDE / Query Normalization
MQE：一个问题 → 多个不同搜索表达，提高 Recall。
HyDE：问题 → 假想答案文档 → 用“像答案的文本”去搜真实文档。
Query Normalization：把非标准表达改成更标准、更稳定的 canonical query。
Canonical Query：系统选定的标准代表表达，例如 “memorizing training set” → “prevent overfitting”。
HyDE 的假答案不是最终事实。它只是 search probe。
16. Retriever vs Reranker
Bi-Encoder Retriever：Query / Document 分别编码成向量，再算 cosine；快，可预计算。
Cross-Encoder Reranker：[CLS] Query [SEP] Document [SEP] 一起进同一个 Transformer，token 可直接 self-attention。
海量候选→ Fast Retriever→ Candidate Pool→ Cross-Encoder→ Final Top-K
Retriever 偏 Recall；Reranker 偏 Precision。
Reranker ≠ 真理机器。更复杂的模型也会受 wording / training distribution 影响。
17. Robustness / Query Wording
Robust / 鲁棒：意思不变、表达方式变化时，系统结果仍然稳定。
如果 “prevent overfitting” 表现正常，而 “stop memorizing training set” 就乱排，说明对 wording 不够 robust。
Query normalization 可以减少 wording 带来的误差源，但不会让排序变成绝对正确。
18. Memory + RAG + Agent Routing
MEMORY：需要用户历史 / 偏好 / 目标 / 过往交互。
RAG：需要外部事实 / 技术知识。
BOTH：同时需要个体上下文和外部知识。
DIRECT：两者都不需要。
更合理的 Router：不要硬做四选一，而是分别判断 MEMORY=YES/NO、RAG=YES/NO，再组合。
Question→ Router→ Memory / RAG / Both→ Context→ LLM
19. Parametric Knowledge / RAG / Web Search
Parametric Knowledge：模型训练阶段学进参数里的知识。
RAG Knowledge：本次运行时从外部知识库检索并塞进 Context 的资料。
Web Search：本次运行时真正访问互联网得到的新信息。
模型在 Context 不充分时，可能主动调用自己的参数知识补空白；这不是偷偷联网。
20. Grounding Policy
STRICT：理论上只允许 Context 中支持的事实。
ASSISTED：Context 做事实基础，同时允许模型用参数知识做分析 / 建议。
Prompt 不是权限边界。写 “Use ONLY the context” 也不能保证模型绝不补充参数知识。
真正严格 grounding：需要 claim validation、citation checking、unsupported claim rejection 等额外机制。
21. 典型 Failure Modes
Router Error：该 BOTH 却只选 MEMORY。
Retriever Error：相关文档没进候选池。
Reranker Error：正确候选被后置模型重新排后。
Generator Error：Context 没写，LLM 自己补事实。
Pipeline Failure：后置模块把前置模块已经修好的结果重新搞坏。
Agent Engineering 的重点：不是“模块越聪明越好”，而是明确职责、边界、失败方式和错误传播。
22. 最终量化 Sandbox 映射
Market Data→ Feature Engine→ Market State→ Agent / Decision Layer→ Python Risk Rules→ Virtual Exchange→ Position / PnL / Logs
模块在量化 Sandbox 中负责什么
Memory之前测试过什么、策略修改历史、用户风险偏好、过往异常事件、长期经验
RAG交易所 API 文档、研究报告、策略说明、风控文档、论文
Structured Data价格、成交量、订单、仓位、PnL、drawdown
Agent决定何时查 Memory、RAG、市场数据、计算工具或调用 Jev
Python确定性计算、风险约束、模拟撮合、账户状态
Jev / LLM非确定性判断、解释、策略建议、自然语言交互
